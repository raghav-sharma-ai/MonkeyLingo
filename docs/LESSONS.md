# MonkeyLingo: Standing Lessons Learned

| ID | Mistake We Made | Fix We Adopted | Rule to Follow Now |
| :--- | :--- | :--- | :--- |
| **L1** | **Scope explosion**: initial PRD was a 4-week research plan with 18 requirements for a 9-day challenge. | Ship a P0 end-to-end baseline first, add performance layers after. Cut in order: cloning mode, best-of-N takes, audio-LLM notes, music mixing, visual polish. | Always maintain a working, reproducible end-to-end demo before layering optimizations. |
| **L2** | **Gnani TTS capabilities**: assumed emotion and pitch parameters existed on REST endpoint. The documented API only exposes text, voice, language, speed, and audio_config. | Verify API capabilities in official docs or test calls before designing around them. Control performance indirectly via speed, text shaping, voice choice, best-of-N, and post-DSP. | Never assume undocumented parameters work; test API with curl/script first. |
| **L3** | **Gnani STT limitation**: returns transcript only in documented response and caps at 30 seconds per file. | Obtain word timings from local Whisper alignment, chunk audio per line, and never assume word timestamps from standard STT. | Segment with Whisper locally; use STT for round-trip ASR validation only. |
| **L4** | **Rights & Consent**: copyrighted movie scenes carry DMCA takedown and disqualification risk. | Only use own, consented, or openly licensed video. Enforce a mandatory consent checkbox in the UI and label all output as AI-assisted synthetic dub. | Block processing if user has not verified rights and consent. |
| **L5** | **Credit burn**: credit-to-second conversion rate was unknown initially. | Log credits per call to `out/credits.csv`, cache every API response by hash, never regenerate full scene, use mock audio in development, and enforce daily caps. | Hash-cache every external API call; show credits used transparently in UI. |
| **L6** | **Prosody assumptions**: assumed punctuation automatically controls emotion. | Treat punctuation shaping as an empirical hypothesis; test punctuation effects per voice. | Calibrate punctuation effects before relying on them for emotional delivery. |
| **L7** | **Translation length mismatch**: Indian-language translations naturally expand and exceed English slot duration. | Give the translation layer a strict character/syllable budget derived from duration times characters-per-second; offer shorter alternates. | Re-translate shorter instead of unnaturally slowing or warping audio. |
| **L8** | **Lip-sync distortion**: stretching or delaying audio beyond ±12% creates slurred, slow-motion speech. | Never stretch audio beyond ±10-12%. Align mouth onset via silence trimming and split sentences into natural sub-sentence clauses matching visual breaths. | Lock speech onset to mouth movement; let vocal decay conclude naturally. |
| **L9** | **Metrics honesty**: presenting fabricated benchmark numbers in demo or posts. | Show only measured values (duration error %, round-trip WER, F0 correlation). Mark missing ones honestly as not measured. | Report real numbers even if gains are modest. |
| **L10** | **Full disclosure**: pretending synthetic dubbing was recorded by human voice artists. | Disclose all AI tools used (Gnani Timbre, Gemini Flash, Whisper, Rubberband) and mark output clearly as synthetic dubbing. | Always label media as AI-assisted synthetic localization. |
| **L11** | **Buggy LLM code**: free-tier and large models can generate subtle bugs in audio code. | Keep tasks small, write one test per module, run tests yourself, commit often, and inspect git diffs before declaring completion. | Never assume generated code works without executing and verifying it. |
| **L12** | **Security & Keys**: accidentally leaking API keys or running unvalidated commands. | Store keys strictly in `.env` read by backend only; never transmit keys to browser; add `.env` to `.gitignore`; validate uploads with ffprobe. | Never trust user-provided filenames; validate MIME and duration server-side. |
| **L13** | **Contest timing**: spending too much time over-engineering a complex web framework when judging focuses on the core pipeline. | Keep web stack minimal (FastAPI + Vanilla JS + HTML/CSS in one column $\le 880$px); no React, no build steps. | The web UI must remain lightweight, tool-like, and never block pipeline execution. |
| **L14** | **Incomplete renaming**: renaming a product partially leaves conflicting titles, docs, and references across repo. | When renaming, execute across code, docs, titles, configs, and assets in a single pass, then run a repo-wide grep to verify zero residual occurrences. | Verify all product references with `grep -rnw` before completing rename milestone. |
| **L15** | **Serverless deployment boundaries**: deploying a heavy media processing pipeline (ffmpeg, rubberband, whisper) to standard serverless platforms (Vercel) fails due to missing C-libraries, file timeouts, and 250MB size limits. | Decouple web presentation / API interface from heavyweight media rendering, configure lightweight vercel routing, and document standalone host or micro-service execution for heavy DSP workloads. | Keep serverless functions scoped to I/O and orchestration; offload heavy DSP and PyAV binaries to dedicated runtimes. |
